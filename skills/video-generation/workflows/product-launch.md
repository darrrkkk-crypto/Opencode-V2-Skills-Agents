# Product and feature launches

Use for launches, version releases, and feature demonstrations of technology products, AI, SaaS, and developer tools. Real UI, honest comparisons, and surprising outputs give viewers evidence and explain value better than slogans. Local revisions to an existing launch film retain the established information order

## Four launch modes

| Mode | Suitable products | Narrative and images | Rhythm |
| --- | --- | --- | --- |
| Real task sequence | Productivity tools, AI products, SaaS | Natural-language instruction → automated work → surprising result | Make key steps understandable, compress waiting, and hold the result longer |
| Output montage | Generative models, rendering, or design products | Show many high-quality, distinct outputs in succession | A strong example every second, with cuts on musical beats |
| Problem versus solution | Disruptive products, new productivity tools | Split-screen or before/after comparison: the same task moves from a difficult old workflow to one step in the new solution | The old approach is cool, flat, and slow; the new one is warm, bright, and crisp |
| Brand or version reveal | Annual updates, strategic launches | Build tension, reveal the breakthrough, and finish with the logo or version | For social publication, retain viewers with information, movement, and sound in the first two seconds; give the brand a full hold at the end |

## Five subtypes of a real task sequence

| Subtype | Demonstration path | What viewers should believe |
| --- | --- | --- |
| Agent delivery | Instruction or file input → task breakdown and execution → interactive output | The product can turn intent into an actual delivery |
| Claim, then measure | Make a performance claim, then show side-by-side runs and metrics | Results can be checked, with evidence for speed or effectiveness |
| Cross-device continuation | Start on desktop → receive a phone notification → view a report on a tablet | A task can continue across devices |
| Drill from chart to source | Dashboard → original table or code | Summaries have sources, and the product stays open |
| Variant generation | Generate four styles from the same input with one click, then show them side by side | One creative starting point can produce meaningful choices |

Choose the example that best expresses this product's value, joining real operations into a comprehensible path

## Assign the dominant information in each section

Shot design should answer three questions together: what viewers learn in this section, where they mainly look, and which audiovisual channel carries the information. Images, speech, and text work around the same focus; when several channels compete for attention, split the beat or extend the hold so viewers can receive them in sequence

The example below is an information-dense 30-second launch film. A simple product can use fewer beats; arrange them according to the actual information while fully retaining the trigger, change, and result

| Time | Narrative task | Image | Sound | Dominant channel |
| --- | --- | --- | --- | --- |
| 0–2s | Show a surprising output or headline metric first | The strongest result appears immediately, with movement guiding viewers into the key information | A strong downbeat or synchronized action sound enters on the first frame | Visual impact + headline |
| 2–12s | Enter a natural-language instruction | Push toward the input field, showing typing and the click | Keyboard sound, click | Image-led |
| 12–20s | Show task breakdown and fast execution | Steps advance at about 3× speed, with responses across devices | Rhythm builds; a chime marks each completed step | Image + SFX |
| 20–26s | Compare key metrics | Split-screen comparison, numbers counting up | Voice-over states the improvement multiple | Subtitles + voice-over |
| 26–30s | Land the brand and CTA | Logo settles, with a beta or access-entry card | Music resolves and fades out | Visual CTA |

This workflow still owns product expression when a launch film uses Motion Graphics; read the [Motion Graphics rendering guidance](../references/motion-graphics.md) as needed for the actual animation

## Preserve product credibility and demonstration readability

For social publication, choose the pace using [shot density](../capabilities/model-video-generation.md#shot-density), and describe camera pushes, pullbacks, or tracking that follows the operation. Submit video-model shots together according to the [single-request generation rule](../capabilities/model-video-generation.md#default-plan-the-complete-multi-shot-video); real UI and screen recordings follow the existing-footage editing path

Show the product through real UI, screen recordings, or approved designs, presenting features and performance metrics according to confirmed materials. Interface evidence from the real product reduces the feeling that this is only a rendered concept. Read the relevant execution guidance only when new static assets or model clips are actually needed; edit existing screen recordings directly

For UI demonstrations, use a clean starting state and verify that each result appears after its triggering action in the final composite, including the background

Push toward key buttons, fields, or code, commonly magnifying about 1.3–1.5 so phone viewers can read them. Retain the triggering action and completed result, shorten or speed up loading waits, and tighten cursor wandering. Pick two or three of the most valuable steps and let them explain the product's capabilities; this works better than visiting every menu

Pair interactions with a light click and completed results with a chime, aligned to the actions. Use lightweight, simple, modern, forward-moving instrumental music below speech. Usually leave at least 3 seconds at the end for the logo, product name, and access entry point

## Completion checks

- Social videos show the core product, a surprising output, or a convincing result in the first two seconds, with movement and sound engaging viewers together
- Each section has a clear dominant information channel, and viewers can understand key steps
- On-screen text, buttons, and code are readable, with clear screen text for core capabilities and headline metrics
- Metrics and features have supporting materials, and sound is synced to operations and results
- Music is modern and restrained, voices are clear, and the ending includes the logo, product name, and an actionable access point
